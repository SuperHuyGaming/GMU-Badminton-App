# Open-Source Maintainer & Community Manager: Role Guide

## Mission Overview
As an **Open-Source Maintainer & Community Manager**, your mission is to cultivate a welcoming, organized, transparent, and thriving community of contributors across all engineering disciplines. You set the vision, prioritize the roadmap, and maintain repository excellence.

---

## Core Responsibilities

### 1. Issue Triage & Roadmap Management
- Review new GitHub Issues submitted via issue forms within 48 hours.
- Apply standard labels:
  - `good first issue` & `help wanted`: For accessible tasks suitable for newcomers.
  - `bug`: Confirmed defects with clear reproduction steps.
  - `enhancement`: New feature requests aligned with the roadmap.
  - `area:web`, `area:core`, `area:scraper`, `area:infra`: Component labels.

### 2. Pull Request Review Protocol
- Ensure PRs adhere to the [Pull Request Template](.github/PULL_REQUEST_TEMPLATE.md).
- Verify that automated CI checks pass before merging.
- Provide encouraging, actionable, and constructive code review comments.

### 3. Release Engineering & Versioning
- Follow **Semantic Versioning (SemVer 2.0)**:
  - `MAJOR`: Breaking API contract or schema changes.
  - `MINOR`: New features or expanded club scraper support.
  - `PATCH`: Bug fixes and security patches.
- Generate automated changelogs and release notes on GitHub Releases.

### 4. Community Inclusivity & Code of Conduct
- Uphold and enforce the [Contributor Covenant v2.1](CODE_OF_CONDUCT.md).
- Moderate GitHub Discussions and community chat channels.
